# Working Glossary

These definitions are intentionally practical rather than academic.

| Term | Practical meaning |
|---|---|
| Model | The reasoning/generation engine. |
| Assistant | A model presented with instructions, interface and capabilities for user interaction. |
| Agent | A model operating toward an outcome with instructions, context, tools, state and an execution/verification loop. |
| Prompt | Input telling the model what to do or consider now. |
| Project instructions | Durable rules governing how the agent should operate in a project. |
| Context | Information available to the model for the current decision. |
| State | Information that persists beyond one reasoning step/session. |
| Tool | An executable capability the agent can call to inspect or change something. |
| Skill | Reusable operating knowledge/procedure loaded when its job is relevant. |
| API | A defined interface through which software requests data or actions from another system. |
| MCP | A protocol for exposing tools/resources to AI clients through a common interface. |
| Repository | A Git-managed project containing files and their history. |
| Commit | A durable recorded change in Git history. |
| Diff | The exact change between two versions. |
| Branch | An independent line of Git work. |
| Pull request | A proposed set of changes presented for review/merge. |
| Acceptance criteria | Observable conditions proving the requested outcome is complete. |
| Hallucination | Model-generated content presented without sufficient grounding in reality/source evidence. |
| Eval | A repeatable test used to measure whether an AI behaviour meets an expected standard. |
| Orchestration | Coordinating multiple agents/tools/workflows to complete a larger objective. |
