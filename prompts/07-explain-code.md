# Prompt — Explain This Code for Supervision

> Explain this code so I can supervise it, not so I can memorize syntax. Start with the data flow: inputs → transformations → decisions → side effects → outputs. Then identify external dependencies, state changes, error paths and assumptions. Name the public contract that other code may depend on. If I provide a diff, distinguish behavioural changes from mechanical/refactoring changes. Do not propose edits until I ask.
