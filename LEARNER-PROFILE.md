## Coaching strategy

### Move quickly through

- generic explanations of systems, inputs/outputs and feedback;
- basic troubleshooting concepts he can demonstrate;
- procedural thinking and consequence awareness.

### Spend real time on

- AI mental models and uncertainty;
- instruction design and context management;
- Git/GitHub and diffs;
- coding literacy for supervising AI-built software;
- APIs, JSON and authentication concepts;
- MCP and reusable capability surfaces;
- context vs memory vs authoritative state;
- evals and regression testing;
- harnesses and multi-agent architecture;
- production observability and recovery.

### Teaching style

Use:

```text
EXPLAIN
→ MAP TO A SYSTEM ANDRÉ KNOWS
→ ANDRÉ OPERATES IT
→ INSPECT EVIDENCE
→ INDUCE/DIAGNOSE A FAILURE
→ REPAIR
→ VERIFY
→ ANDRÉ EXPLAINS IT BACK
```

Avoid:

- treating him as computer-illiterate;
- turning every lesson into a hydraulic analogy;
- assuming industrial experience automatically transfers to software detail;
- doing exercises for him;
- overloading the course with theory before practical use.
